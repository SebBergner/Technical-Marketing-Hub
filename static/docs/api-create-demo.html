Create a demo through the API

For programs — a pipeline, a script — that create demos in the Technical Marketing Hub the way Create New Demo does on the page: metadata first, files, then review. Written 2026-10-15; SharePoint and Hub URLs in every answer since 2026-10-16; fields and their values listed 2026-10-20.

1. Get a token

An administrator issues it on Admin → Users & groups → API tokens: a name for what uses it, the person responsible, the permissions (Create new demo for this, plus View the Hub), how long it lasts, and whether what it creates is published without review. The token is shown once; keep it in a secret store, not in code.

Send it on every call:

Authorization: Bearer tmh_xxxxxxxx_…

A token reaches /api/ only, acts as token:<name> in the Admin log, and stops working when it expires or is revoked (HTTP 401).

2. The quick way: the script

scripts/create_demo_api.py in the Hub's repository does the whole flow (needs Python and pip install httpx):

# What can be created, and the fields each needs (* = required):
python create_demo_api.py --hub https://tmh.ptcxc.com --token "$TMH_TOKEN" --show-form

# A demo kit: a folder with its sub-folders; several videos -> name the preview.
python create_demo_api.py --hub https://tmh.ptcxc.com --token "$TMH_TOKEN" \
    --target demo_catalog --kind ldk --metadata kit.json \
    --preview "Videos/Overview_CF.mp4" "C:/Demos/Creo Sheetmetal Kit"

# A single video.
python create_demo_api.py --hub https://tmh.ptcxc.com --token "$TMH_TOKEN" \
    --target demo_video --kind video --metadata video.json "Creo Teaser.mp4"

kit.json holds the fields, for example:

{
  "title": "Creo Sheetmetal Kit",
  "description": "Sheetmetal design end to end.",
  "products": ["Creo Parametric"],
  "segment": ["CAD"],
  "customer_facing": true,
  "contains_audio": false,
  "original_publish_date": "2026-09-01",
  "language": "English",
  "owned_by": "Technical Demonstration Development"
}

3. The calls, one by one

StepCallWhat it does
1GET /api/uploads/targetsDestinations, their kinds, and each field: key, kind, required, the allowed choices.
2POST /api/uploadsMetadata and the file list. Checked in full; on success the demo's folder is created and an upload record returned (id, files).
3POST /api/uploads/{id}/files/{n}/sessionAn upload_url for file n.
4PUT {upload_url}The file's bytes, in chunks, straight to the destination (no token on this call — the URL carries its own authorisation).
5POST /api/uploads/{id}/files/{n}/doneThe created item's id; the Hub checks name and size.
6POST /api/uploads/{id}/finishWrites the metadata; the demo waits for review (or is published, if the token says so).
—GET /api/uploads?mine=trueThis token's uploads and where each stands (uploading, pending, sent_back with the reviewer's note, published).
—POST /api/uploads/{id}/resubmitAfter a send-back: {"values": {...}} with the metadata corrected (the title stays).

Where the demo is

Every answer about an upload (steps 2, 5, 6 and the list) carries:

FieldWhat it is
sharepoint_urlThe demo's folder in SharePoint, from step 2 on.
hub_urlA permanent link to the demo in the Hub, from step 2 on. It opens the demo's page once the Hub has read the new folder — a sync starts by itself when the demo is published, usually a few minutes — and My demos until then.
asset_id, asset_urlThe demo's own id and page in the Hub, once it has been read; null before. Poll GET /api/uploads?mine=true if you need them.

Step 2 in detail

POST /api/uploads
{
  "target": "demo_catalog",            // or "demo_video"
  "kind": "ldk",                       // ldk | vdk (Demo Catalog), video (Demo Video)
  "values": { ...the fields... },
  "files": [ {"path": "Videos/Overview_CF.mp4", "size": 52428800},
             {"path": "Script.docx", "size": 20480} ],
  "preview": "Videos/Overview_CF.mp4", // required with two or more videos
  "internal": false,                   // true: files open only for internal access
  "submitted_by": "jane.doe@ptc.com"   // optional: who this upload is for (see below)
}
  • path is where the file goes inside the demo (sub-folders kept); size in bytes, exactly.
  • The title becomes the demo's name; a name already taken is refused (409).
  • A video demo is exactly one video file.
  • submitted_by (optional, since 2026-10-20): for a tool several people use through one token, the PTC email address of the person this upload is for. The token must be allowed to name who it uploads for (a tick when the token is created); otherwise, or for a non-PTC address, the call is refused (422). The person is recorded on the upload, shown to reviewers, and credited as the demo's creator in Hub activity. Without it, the token's responsible person is credited.

The fields and their values

Each target's fields, and for a list field the values it accepts, come from that library's own SharePoint columns. Read them from GET /api/uploads/targets and build your dropdowns from that answer rather than copying the lists below: a new product or language added in SharePoint appears there at once. A value must match exactly, capitals and punctuation included (some Windchill names use the full-width ＆).

targets = requests.get(HUB + "/api/uploads/targets", headers=AUTH).json()["targets"]
for t in targets:                      # demo_catalog, demo_video
    for f in t["fields"]:              # key, label, kind, required, default, choices
        if f["choices"]:
            dropdown(t["key"], f["key"], f["choices"], default=f["default"])

Step 4 in detail: chunks

  • Each chunk a multiple of 320 KiB (the script uses 10 MiB), at most 60 MiB.
  • Header Content-Range: bytes {start}-{end}/{total}.
  • Answer 202: send the next chunk. Answer 200/201: the file is complete — its JSON has the id for step 5.
  • 429 or 5xx: wait (Retry-After) and send the same chunk again.
curl -X PUT "$UPLOAD_URL" -H "Content-Range: bytes 0-10485759/52428800" \
     --data-binary @chunk0

4. Errors

HTTPMeaning
401No token, or it is unknown, expired or revoked.
403The token does not carry the permission (Create new demo, View the Hub).
409A demo with that name already exists.
422The metadata or files: detail lists every problem at once.
502The destination refused or failed; the record keeps the error. Calling finish again retries the last step.

Nothing already in the destination is ever changed or deleted: each demo is a new folder. A run that stops half-way leaves its folder for a person to finish or remove; the record says where it stopped.
